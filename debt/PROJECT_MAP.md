# Карта проекта

## Назначение
Заметка по долгам для GitHub Pages. Пользователь указал опубликованный сайт
https://amedai.github.io/debt/; в локальном `config.js` заполнены URL и публичный ключ
предоставленного проекта Supabase. Обновление конфигурации на GitHub не выполнялось.
В локальной папке `.git` отсутствует; публикация изменений ещё не выполнялась.

## Структура и точки входа
- `index.html` — русскоязычный интерфейс, вкладки, таблица, форма входа и диалоги.
- `styles.css` — адаптивное оформление с БЭМ-классами; `favicon.svg` — иконка.
- `app.js` — ES-модуль интерфейса, обработчики форм, вход, экспорт/импорт JSON.
- `config.js` — экспорт `config` с заполненными публичными параметрами Supabase.
- `core.mjs` — валидация, денежные суммы, копии, `sortRecords`, `existingNames`, `summarizePeople`.
- `storage.mjs` — `localRepository` и `cloudRepository`.
- `supabase.sql` — `debts`, `debt_settings`, примечания, публичное чтение и RLS для записи только владельцем.
- `scripts/serve.mjs` — локальный HTTP-сервер, только разрешённые статические файлы.
- `tests/debt.test.mjs` — тесты логики, совместимости старых записей, сводки и адаптеров; API имитируется.
- `tests/access.test.mjs` — реальный SQL/RLS на PostgreSQL в памяти через PGlite, без Supabase-сервера.
- `tests/interface.test.mjs` — DOM-проверки на LinkeDOM: форма, сортировка, смена аккаунта, перенос.
- `package.json`, `package-lock.json` — команды и зависимости разработки; сайт работает без npm и сборки.
- `.nojekyll` — отключает Jekyll при публикации корня на GitHub Pages.
- `.gitignore` — исключает кэш, зависимости, журналы и `.env`.
- `README.md` — запуск, подключение Supabase, публикация репозитория `debt`.
- Локальные JSON-копии и `import-debts.sql` исключены из Git (`.gitignore`).
- `import-debts.sql` — подготовленный перенос предоставленной копии через SQL Editor после
  `supabase.sql`; берёт владельца из `debt_settings`, пропускает существующие ID.

## Данные и ограничения
- Пустой `config.js`: localStorage с ключом `debt.records.v1` (`core.mjs`).
- Настроенный `config.js`: публичный список без входа; изменения после входа владельцем (`app.js`).
- UUID владельца хранится в `debt_settings`, меняется только в SQL Editor;
  в `supabase.sql` указан предоставленный UUID. Все изменения скрипта выполняются в транзакции.
- RLS и права SQL запрещают посетителю менять долги и настройки; чужому аккаунту запрещена запись,
  включая обход через постороннюю разрешающую политику (`supabase.sql`, `tests/access.test.mjs`).
- При ошибках облака перехода к локальной записи нет (`app.js`).
- SDK Supabase 2.118.0 загружается с jsDelivr только в облачном режиме (`app.js`).
- Записи хранят суммы целым числом копеек; итоги и сводка считаются через BigInt (`core.mjs`, `app.js`).
- Примечание `note` до 2000 символов, отсутствующее в старой записи превращается в пустую строку.
- `personKey` объединяет регистр и пробелы в именах; сводка включает обе вкладки и разницу.
- Сортировка по имени в обе стороны или по дате не меняет порядок хранения (`core.mjs`, `app.js`).
- Лимит клиента — 10 000 записей; импорт до 10 МБ (`core.mjs`, `app.js`).
- JSON-копия содержит обе вкладки, без `user_id`; импорт добавляет новые ID (`storage.mjs`).
- Облако читается страницами по 500 строк; новые данные загружаются по кнопке
  при возвращении на страницу и каждые 30 секунд видимой вкладки без открытых диалогов,
  без Realtime (`storage.mjs`, `app.js`).
- «Перенести из браузера» доступно владельцу, сохраняет локальный оригинал и добавляет новые ID;
  перенос возможен только с того же origin, на другом устройстве нужен JSON (`app.js`).
- Одновременное изменение одной записи: последнее сохранение побеждает (`storage.mjs`).
- Относительные пути позволяют размещать сайт в `/debt/` (`index.html`, импорты JS).

- `npm.cmd start` / `node scripts/serve.mjs` — http://127.0.0.1:4173.
- Проверены HTTP 200 для семи статических ресурсов и HTTP 404 для четырёх закрытых путей.
- Проверены соответствие ID из `app.js` разметке и отсутствие дублей ID.
- Публичный URL закреплённой версии SDK вернул HTTP 200.
- Визуальная проверка не выполнялась: подключённых браузеров в среде нет.
- RLS проверен локально на PostgreSQL. URL и публичный ключ настоящего проекта проверены:
  GET `/auth/v1/settings` вернул HTTP 200. UUID владельца заполнен в `supabase.sql`.
- Применение SQL в настоящем проекте подтверждено: публичные GET `/rest/v1/debt_settings`
  и `/rest/v1/debts` вернули HTTP 200, владелец совпадает с предоставленным UUID.
  На момент проверки облачный список пуст; опубликованный `config.js` ещё не обновлён.
- Настоящий вход и обмен между устройствами пока не проверены.
