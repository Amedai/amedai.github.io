# debt — заметка по долгам

Две вкладки: **Мне** (мне должны) и **Я** (я должен). В каждой таблица
**Название / Примечание / Сколько / Кто**, добавление, изменение, удаление с подтверждением,
сортировка по имени А → Я / Я → А или по дате. В форме можно выбрать имя из существующих
или ввести новое. Общая сводка по людям показывает обе стороны долга и итоговую разницу.
Суммы — в рублях, хранятся в целых копейках.
Страница адаптирована для телефона; широкую таблицу можно прокручивать по горизонтали.

Сайт статический: работает на GitHub Pages, без сборки и установки зависимостей.
Опубликованный сайт: **https://amedai.github.io/debt/**.
Для общего списка нужно один раз подключить Supabase: до этого записи остаются в браузере.

## Открыть на компьютере

Установлен Node.js? Выполните в этой папке:

```powershell
npm.cmd start
```

Откройте **http://127.0.0.1:4173**. Остановить сервер: `Ctrl+C`.
Не открывайте `index.html` двойным щелчком: браузер блокирует ES-модули по `file://`.

## Как хранятся записи

Пока `config.js` пустой, данные сохраняются **только в текущем браузере**.
Другая ссылка, другой браузер, другое устройство или очистка данных сайта —
другое/пустое хранилище. «Скачать копию» выгружает обе вкладки в JSON.

Для одного списка с телефона и компьютера подключите Supabase по шагам ниже.
При заполненном `config.js` сайт показывает всем один список из базы без входа.
Добавлять, менять, удалять и импортировать записи может только владелец после входа;
это ограничение действует в базе через RLS, в том числе для прямых запросов к API.
Имена, суммы и примечания в общем списке видны каждому, кто откроет сайт.
При ошибке связи сайт показывает ошибку;
при ошибке связи записи не переключаются незаметно в локальный режим.
Для изменения облачных записей нужен интернет. Список обновляется при возвращении
на страницу, каждые 30 секунд в открытой вкладке и по кнопке «Обновить».
При открытом диалоге автоматическое обновление приостанавливается.
Если два устройства изменили один долг, сохранится последнее изменение.

## 1. Подключить хранение в интернете

1. Откройте [Supabase](https://supabase.com/dashboard) и выберите свой проект.
   Если проекта ещё нет, создайте `debt`.
   Выберите подходящий вам тариф. Пароль базы сохраните у себя: сайту он не нужен.
2. Откройте **Authentication → Users**. Если ваш пользователь уже существует, используйте его:
   это важно для сохранения доступа к уже облачным долгам. Если нет — **Add user → Create new user**.
   Укажите свою почту и пароль; для созданного вручную пользователя включите
   **Auto Confirm User**, если этот пункт показан. Этой почтой и паролем
   будете входить на сайте, когда нужно изменить записи. Скопируйте **UUID** этого пользователя.
3. В текущем `supabase.sql` UUID вашего пользователя уже заполнен.
   В Supabase откройте **SQL Editor → New query**, вставьте весь файл и нажмите **Run**.
   При подключении другого аккаунта сначала измените UUID в строке `values (true, ...)`.
   Скрипт создаёт таблицы и правила доступа; при обновлении старой базы добавляет примечания,
   сохраняя долги. Его можно выполнить повторно. Без корректного UUID весь скрипт откатится.
   В общем списке появятся только строки с `user_id` выбранного владельца;
   записи других аккаунтов останутся в базе и не будут опубликованы.
4. В диалоге **Connect → API Keys** либо в **Project Settings → API Keys**
   скопируйте **Project URL** и **Publishable key**. Старый **anon key** тоже поддерживается.
5. Заполните `config.js`:

```javascript
export const config = Object.freeze({
  supabaseUrl: "https://YOUR_PROJECT.supabase.co",
  supabaseKey: "sb_publishable_ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ",
});
```

Публичный ключ предназначен для размещения в браузере. Доступ к записям
ограничивает RLS в `supabase.sql`: все читают долги владельца, только он может их менять.
Владелец задаётся в таблице `debt_settings` через SQL Editor, посетители не могут его заменить.
**Secret key, service_role, пароль аккаунта и пароль базы в репозиторий не добавляйте.**
Пароль для входа вводится только в форме сайта.

Перед подключением на **https://amedai.github.io/debt/** в браузере с вашими долгами нажмите
**«Скачать копию»**. После подключения войдите через **«Войти для изменений»**.
На том же устройстве и в том же браузере нажмите **«Перенести из браузера»**:
записи добавятся в облако, локальная копия сохранится. На другом устройстве выберите
**«Загрузить копию»** и скачанный JSON. Импорт добавляет только неизвестные
идентификаторы; существующие записи не заменяет. Пустая или некорректная копия
не удаляет текущие данные. Поддерживается до 10 000 записей и файл до 10 МБ.

Для переданного файла `debt-2026-10-18.json` подготовлен локальный `import-debts.sql`.
После настройки владельца через `supabase.sql` откройте **SQL Editor → New query**,
вставьте весь `import-debts.sql` и нажмите **Run**. Результат `added_records` покажет,
сколько новых записей добавлено. Повторный запуск пропускает существующие ID и не меняет
ранее внесённые долги. Затем на сайте нажмите **«Обновить»**.
JSON и SQL переноса не нужны для сайта и исключены из Git через `.gitignore`.
Вместо SQL можно войти владельцем и выбрать исходный JSON через **«Загрузить копию»**.

## 2. Обновить ваш сайт на GitHub Pages

1. Откройте [репозиторий amedai/debt](https://github.com/amedai/debt).
   Загрузка кода не загружает сами записи: они остаются в браузере или Supabase.
2. Через **Add file → Upload files** обновите файлы проекта в корне репозитория и сохраните коммит в ветку, выбранную в Pages.
   Для работы сайта нужны `index.html`, `styles.css`, `favicon.svg`, `app.js`,
   `config.js`, `core.mjs`, `storage.mjs` и пустой `.nojekyll`.
   Можно загрузить весь исходный проект, кроме того, что перечислено в `.gitignore`.
3. Настройки Pages на уже работающем сайте менять не нужно. Дождитесь успешной публикации в **Actions**.
4. Откройте **https://amedai.github.io/debt/** на телефоне или в другом браузере:
   список должен быть виден без входа, кнопок добавления и изменения быть не должно.
5. Нажмите **«Войти для изменений»** и войдите своим аккаунтом владельца.
   Добавьте запись, откройте сайт в другом браузере и нажмите «Обновить»:
   запись должна появиться, редактирование по-прежнему доступно только вам.

Все пути в коде относительные: отдельная настройка для подпапки `/debt/` не нужна.
Для сайта не нужны `node_modules`, `.cache`, `tests`, `package-lock.json` или сборка.

Официальные инструкции: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site),
[ключи Supabase](https://supabase.com/docs/guides/getting-started/api-keys),
[правила доступа RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

## Проверка кода

```powershell
npm.cmd ci --cache .cache/npm
npm.cmd run check
```

Проверяет синтаксис JavaScript и запускает тесты расчётов, копий,
локального хранения и облачного адаптера с имитацией API.
SQL проверяется на тестовом PostgreSQL в памяти (`@electric-sql/pglite`): посетитель,
чужой аккаунт, владелец, прямые запросы, обновление старой базы и повторный запуск скрипта.
DOM-проверки на LinkeDOM проверяют форму, сортировку, просмотр без входа, выход и перенос.
Тестовые зависимости нужны только для разработки.
Настоящий вход и обмен между устройствами нужно проверить после подключения
вашего проекта Supabase. Визуальная проверка требует подключённого браузера.
