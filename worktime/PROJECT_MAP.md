# Карта рабочей папки

- `debt/` — предоставленный проект учёта долгов; в этой задаче не изменяется.
- `worktime/` — новый независимый статический трекер для GitHub Pages.
- `worktime/index.html`, `styles.css`, `app.js` — интерфейс, оформление, управление состоянием.
- `worktime/core.mjs` — проверки данных, даты, оплата, `transitionTimer`, `workBill`, `timerClock`.
- `worktime/storage.mjs` — отдельные облачные таблицы и локальный демонстрационный режим.
- `worktime/config.js` — публичная конфигурация существующего Supabase.
- `worktime/supabase.sql` — отдельные таблицы, ограничения и RLS владельца.
- `worktime/tests/` — расчёты, хранилище, DOM и PostgreSQL/RLS.
- `worktime/README.md` — запуск и самостоятельная публикация нового репозитория.

Облачный режим не заменяется локальным при ошибке. `?demo=1` явно включает
изолированное локальное хранилище для знакомства с интерфейсом. Рабочие задачи
видны посетителям, запись разрешает RLS только владельцу существующего аккаунта.
Расчёт каждой записи независим: `floor(минуты / 10) × 200`; сумма считается
при чтении, производную стоимость в базе не храним. У таймера сначала складываются
активные миллисекунды всей задачи, паузы исключены, затем применяется округление.
В общую сводку входят завершённые записи; текущий таймер показывает оценку отдельно.

Ввод и отображение дат, дата страницы и фильтр по месяцу используют `Europe/Moscow`
(`core.mjs`: `TIME_ZONE`, `localInput`, `moscowInputToISO`). В форме отдельные поля
даты и времени `ЧЧ:ММ` без AM/PM; `app.js` переводит ввод МСК в UTC для хранения.

## Таймер

- `timer_state`: `manual` (старый интервал), `running`, `paused`, `finished`.
- `elapsed_ms` хранит накопленное активное время, `running_since` — начало
  текущего отрезка; `timer_version` защищает команды от повторов (`core.mjs`).
- Единственный незавершённый таймер во всех проектах: проверка данных на клиенте,
  частичный уникальный индекс `worktime_one_timer` в SQL.
- `storage.mjs`: локальный `timerAction` проверяет версию; облачный вызывает
  `worktime_timer_action`. Сервер блокирует строку и использует своё время.
- `app.js`: отдельная панель, обновление секунд без запросов к базе каждую секунду;
  единая кнопка «Начать работу» и запуск из планов. Новые рабочие задачи всегда
  запускают таймер без ввода окончания; его сохраняет «Завершить». Старые ручные
  интервалы редактируются с окончанием. При обновлении страницы отсчёт восстанавливается.
- SQL добавляет новые поля существующей таблице; старые записи остаются `manual`.
- Импорт/экспорт: версия 2 с полями таймера; загрузка версии 1 поддерживается.

## Проверенные команды и ограничения

- Из `worktime/`: `npm.cmd start`, локальный адрес `http://127.0.0.1:4174`.
- `npm.cmd run check`: синтаксис модулей и 39 тестов расчётов, времени МСК, таймера, адаптеров, SQL/RLS и DOM.
- Тесты `core.test.mjs` и `interface.test.mjs` также прошли при `TZ=America/Los_Angeles`.
- `worktime/package-lock.json` создан npm; зависимости нужны только для тестов.
- Публичные параметры переиспользованы из исходного проекта; SQL подготовлен,
  но в настоящую базу не применялся. Настоящий вход не проверялся.
- Подключённых браузеров нет: визуальная проверка не выполнена.
- Развёртывание на GitHub Pages не выполнялось; шаги в `worktime/README.md`.
- Импорт через `worktime_import` атомарный и не перезаписывает известные ID.
- Нет сборки. Публикуется содержимое `worktime/`, без родительской папки `debt/`.
- Локальный сервер проверен: семь ресурсов возвращают HTTP 200, пять закрытых
  путей (SQL, документация, зависимости, соседний проект) — HTTP 404.
- Проверка Supabase REST API запросами `select=*&limit=0` подтвердила HTTP 404 /
  `PGRST205` для `worktime_settings`, `worktime_projects`, `worktime_items`:
  API не находит таблицы в schema cache. Требуется выполнить `supabase.sql`
  в SQL Editor проекта из `config.js`; подключённого доступа к панели нет.
