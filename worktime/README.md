# Worktime — время в дело

Отдельный проект для GitHub Pages. Проекты, журнал выполненной работы и вкладка
«Планы». На странице видны задачи, время и стоимость. Создавать, изменять,
удалять и импортировать облачные записи может только владелец после входа.
Посетителям доступен просмотр, включая названия, примечания и суммы.
Права проверяются в PostgreSQL через RLS, а не только скрытием кнопок.

## Как считается стоимость

Каждый рабочий интервал: `floor(длительность в минутах / 10) × 200 ₽`.
9 минут = 0 ₽, 10 = 200 ₽, 19 = 200 ₽, 25 = 400 ₽, 60 = 1200 ₽.
Остатки разных интервалов не складываются: две записи по 9 минут = 0 ₽.
У таймера все активные отрезки одной задачи сначала складываются, затем
округляются: 6 минут работы + перерыв + 6 минут работы = 12 минут = 200 ₽.
Общая стоимость — сумма завершённых записей. Работающий и приостановленный
таймер показывает предварительную стоимость отдельно, до завершения задачи.

В форме указываются дата и время начала и окончания. Работа после полуночи
допускается: укажите следующую дату окончания. Конец должен быть позже начала,
ручная запись ограничена семью днями. Даты хранятся в UTC; ввод, просмотр и фильтр
по месяцу используют часовой пояс устройства. Для одной задачи можно создавать
несколько записей с одинаковым названием и разными интервалами.

## Таймер с паузами

1. Нажмите **«▶ Таймер»** рядом с «Записать работу». Укажите проект, задачу
   и время начала — по умолчанию текущее, можно выбрать более раннее.
2. Нажмите **«Пуск»**. Появится панель с активным временем и текущей стоимостью.
3. Уходя на перерыв, нажмите **«Пауза»**. Отсчёт остановится, перерыв не оплачивается.
4. Вернувшись, нажмите **«Продолжить»**. Предыдущее активное время сохранится.
5. Нажмите **«Завершить»**. В журнале останется одна запись с суммарным рабочим
   временем без пауз и окончательной стоимостью. Завершить можно и на паузе.

Таймер можно запустить кнопкой ▶ у задачи из «Планов» — задача переместится
в журнал с прежними названием и примечанием. Одновременно ведётся одна задача:
перед запуском другой завершите текущую, в том числе поставленную на паузу.

Обновление или закрытие страницы не останавливает работающий таймер;
пауза также сохраняется. Отсчёт восстанавливается по сохранённым меткам времени,
поэтому спящий компьютер и свёрнутая вкладка не сбрасывают секунды.
В облачном режиме для пуска, паузы, продолжения и завершения нужен интернет.
Действие считается выполненным после успешного ответа хранилища; при ошибке
связи проверьте состояние кнопкой «Обновить». Облачные переходы используют время
сервера и версию записи, чтобы повторное нажатие не добавляло время дважды.
При изменении таймера на другом устройстве панель обновится при синхронизации.

Название, проект и примечание завершённого таймера можно исправить; его время
при этом сохраняется с учётом пауз. Вручную введённые интервалы редактируются
как прежде. Новые копии имеют версию 2; копии версии 1 по-прежнему загружаются.

**Если облако уже было подключено:** повторно выполните целиком обновлённый
`supabase.sql` в SQL Editor, затем загрузите обновлённые файлы сайта на GitHub
и нажмите «Обновить». Скрипт добавит поля и функцию таймера, сохранив старые
задачи и их стоимость. Настоящая база при разработке не изменялась.

## Быстро посмотреть на компьютере

В терминале откройте эту папку `worktime` и выполните:

```powershell
npm.cmd start
```

Для локального знакомства откройте **http://127.0.0.1:4174/?demo=1**.
Зависимости для запуска сайта не нужны, достаточно Node.js.
Двойной щелчок по HTML не подходит: нужны ES-модули через HTTP.
Остановить сервер: `Ctrl+C`.

Демо явно помечено и хранится только в браузере, без входа и синхронизации.
Оно не меняет рабочую базу. Для переноса скачайте копию в демо и загрузите её
в облачном режиме после входа. Параметр `?demo=1` не даёт права менять облако.
При сбоях облака автоматического переключения на локальную запись нет.

## Подключить облако: один раз

`config.js` уже содержит URL и публичный ключ того же Supabase, что у проекта
с долгами. В `supabase.sql` указан тот же UUID владельца. Новые таблицы
`worktime_settings`, `worktime_projects`, `worktime_items` независимы от долгов.

1. Откройте **существующий проект** в [Supabase Dashboard](https://supabase.com/dashboard).
2. Выберите **SQL Editor → New query**.
3. Вставьте целиком содержимое `supabase.sql` и нажмите **Run**.
   Скрипт можно выполнять повторно: существующие записи сохраняются.
4. Откройте **http://127.0.0.1:4174/** и нажмите «Обновить».
5. Нажмите **«Войти для изменений»**, введите почту и пароль своего
   существующего пользователя Supabase из проекта с долгами.
6. Создайте проект и запишите первый рабочий интервал.

Аккаунт GitHub для входа в трекер не используется. Пароль Supabase вводится
только в форме входа, в файлах проекта его нет. Secret key, service_role и
пароль базы в `config.js` или GitHub добавлять нельзя. Публичный ключ допустим
в браузере; ограничение на запись обеспечивают SQL-права и RLS.
При использовании другого Supabase измените публичные параметры в `config.js`
и UUID владельца в `supabase.sql` перед запуском скрипта.

Подробности: [RLS Supabase](https://supabase.com/docs/guides/database/postgres/row-level-security),
[вход по паролю](https://supabase.com/docs/reference/javascript/auth-signinwithpassword).

## Опубликовать отдельным сайтом на GitHub Pages

1. Создайте новый репозиторий, например **worktime**.
2. Загрузите **содержимое папки `worktime` в корень репозитория**,
   чтобы `index.html` лежал в корне. Папку `debt` загружать не нужно.
3. Для сайта нужны `index.html`, `styles.css`, `favicon.svg`, `app.js`,
   `config.js`, `core.mjs`, `storage.mjs` и `.nojekyll`.
   Документацию, SQL и тесты тоже можно хранить в репозитории.
   Не загружайте `node_modules`, `.cache`, `.env`, скачанные копии с задачами.
4. Откройте **Settings → Pages → Build and deployment**.
   Выберите **Deploy from a branch → main → / (root) → Save**.
5. После завершения публикации адрес для `amedai/worktime` будет
   **https://amedai.github.io/worktime/**.
   Этот адрес предполагаемый; в рамках разработки сайт туда не публиковался.
6. Проверьте сайт без входа: задачи видны, действий редактирования нет.
   Войдите владельцем, создайте запись, откройте сайт на другом устройстве
   и нажмите «Обновить»: запись должна появиться.

Сборка и GitHub Actions не нужны. Пути относительные и подходят для подпапки
`/worktime/`. [Официальная инструкция GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

## Работа и планы

- Выберите проект слева или «Все проекты». Добавление, переименование и удаление
  пустого проекта доступны владельцу. Проект с задачами удалить нельзя;
  задачи можно перенести в другой проект в редакторе.
- В журнале добавьте название, начало, окончание и при необходимости примечание.
  До сохранения виден расчёт. Есть поиск, выбор месяца и «За всё время».
- Во вкладке «Планы» запишите будущие задачи. Галочка меняет статус готовности,
  значок часов открывает форму времени. После сохранения эта задача переносится
  в журнал с прежним ID и примечанием; второй экземпляр не создаётся.
- Сводка учитывает выбранный проект и месяц, но не текст поиска.
  Планы не ограничены месяцем; счётчик показывает только невыполненные задачи.
- «Скачать копию» сохраняет все проекты и обе вкладки в JSON.
  «Загрузить копию» добавляет неизвестные ID; существующие не заменяются.
  Импорт в облаке атомарный: ошибка не оставляет частично загруженные данные.
- При входе на другом устройстве используются тот же аккаунт и та же база.
  Обновление — по кнопке, при возвращении на страницу и каждые 30 секунд.
  При открытой форме обновление приостанавливается. Одновременные изменения
  одной задачи сохраняются по принципу последнего успешного сохранения.

## Проверки для разработки

```powershell
npm.cmd ci --cache .cache/npm
npm.cmd run check
```

35 тестов: оплата и границы времени, копии, локальный и облачный адаптеры,
PostgreSQL/RLS через PGlite, сценарии интерфейса через LinkeDOM. Проверяются
паузы, продолжение, завершение, восстановление таймера, сохранение секунд,
миграция старой схемы, запрет второго таймера и устаревших команд.
Синтаксис всех рабочих JS-модулей проверяется перед тестами.
Браузерная визуальная проверка, настоящий вход и обмен между устройствами
в этой среде не выполнялись. Применение SQL и публикация требуют ваших
аккаунтов Supabase и GitHub.
